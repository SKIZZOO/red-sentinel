# Red Sentinel

A polished web command center for Red-DiscordBot.

## What this project gives you

- Dark, animated, responsive Netlify dashboard.
- Red cog with an `aiohttp` API server.
- Live Discord event/audit logging into local SQLite.
- Web moderation: ban, kick, timeout, message deletion.
- Rich announcement composer with embeds.
- Social signal routing for Twitch, YouTube, Kick, X/Twitter and custom providers.
- Signed webhook endpoint for external social automation.
- Discord OAuth2 login option.
- Static API-token option for private/self-hosted installs.
- Server-side storage of bot/provider secrets.

## Architecture

```text
Browser (Netlify)
      |
      | HTTPS / JSON
      v
Red Sentinel API (runs beside Red)
      |
      +--> Discord / Red
      +--> SQLite event store
      +--> Social webhook router
      |
      +--> Twitch / YouTube / Kick / X adapters (provider-specific)
```

**Important:** Netlify is the frontend host. It should not contain your Discord bot token or social API secrets. The long-running API belongs on the same machine/service as Red.

## Install the cog

Copy `cogs/red_sentinel` into your Red custom cog path, then:

```text
[p]load red_sentinel
[p]sentinel token
```

The token is DM'd to the command invoker.

For a repository-based install, once the project is pushed to GitHub:

```text
[p]repo add red-sentinel https://github.com/YOUR_GITHUB_USER/red-sentinel
[p]cog install red-sentinel red_sentinel
[p]load red_sentinel
```

Red's official cog system uses repository -> cog install -> load, and cog setup functions call `bot.add_cog(...)`.

## Dashboard / Netlify

The `dashboard/` folder is a static site. You can deploy the repo through Netlify's Git integration or drag/drop the dashboard folder.

Set:

- API URL = the public HTTPS URL of your Red Sentinel API
- API token = the token generated by `[p]sentinel token`

For production, configure Discord OAuth in the cog and use **Login with Discord** instead of a static token.

## Discord OAuth setup

Create an application in the Discord Developer Portal.

Add a redirect URI:

```text
https://YOUR-RED-API-HOST/oauth/discord/callback
```

Then configure the cog's Red Config values. The cog requests `identify guilds` and only exposes guilds where the logged-in user has Administrator or Manage Server permission.

Never put the Discord bot token or OAuth client secret into Netlify frontend code.

## Social integrations

The cog deliberately exposes a provider-neutral signed endpoint:

```text
POST /api/webhooks/social
X-Sentinel-Webhook: YOUR_SENTINEL_API_TOKEN
Content-Type: application/json
```

Example:

```json
{
  "provider": "twitch",
  "item": {
    "title": "Streamer is live!",
    "author": "StreamerName",
    "description": "Playing something awesome",
    "url": "https://twitch.tv/StreamerName",
    "thumbnail": "https://..."
  }
}
```

This lets you connect official provider webhooks, n8n, Make, Zapier, or a small worker. Provider API credentials stay server-side.

The routing UI maps:

- `twitch` -> Discord channel
- `youtube` -> Discord channel
- `kick` -> Discord channel
- `x` -> Discord channel
- `custom` -> Discord channel

## Recommended production hardening

1. Put the Red Sentinel API behind HTTPS (Caddy, Nginx, Cloudflare Tunnel, or your host's reverse proxy).
2. Set `netlify_origin` to the exact Netlify site origin instead of `*`.
3. Prefer OAuth over a static API token.
4. Use a firewall so the Red host exposes only the reverse-proxy port.
5. Keep the bot's role below roles it should never moderate.
6. Give the bot only the Discord permissions it actually needs.
7. Set a finite event retention period if your server is busy.
8. Treat Discord OAuth secrets, provider secrets and the sentinel token as passwords.

## Current scope

This is a production-oriented foundation, not a claim that every provider's current API contract is identical. Twitch, YouTube, Kick and X change their API/webhook requirements over time, so provider-specific workers should be configured against their current official API credentials and event contracts.
